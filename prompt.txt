You are a senior Android + backend engineer. I want you to build a production-ready Azan (Adhan) Android application with an admin-controlled prayer schedule.

PROJECT GOAL
Build an Android app where an administrator controls the daily prayer/Azan schedule from a web-based admin panel. Users install the Android APK, sync the schedule, and the phone automatically plays a pre-recorded Azan audio at each scheduled prayer time—even when the app is closed and the phone is locked, subject to Android OS restrictions.

CORE ARCHITECTURE

1. ANDROID USER APP
- Native Android application using Kotlin.
- Modern Android architecture.
- Jetpack Compose for UI.
- Local persistent database using Room.
- WorkManager where appropriate.
- AlarmManager for exact prayer-time scheduling.
- Firebase Cloud Messaging for configuration updates.
- Local audio playback for Azan.
- The app must NOT depend on an internet connection at the exact prayer time.
- Once the schedule is synchronized, prayer alarms should be stored locally.
- Handle device reboot and reschedule alarms.
- Handle timezone changes.
- Handle date changes.
- Handle Android Doze/battery optimization as reliably as Android allows.
- Handle Android 12+ exact alarm restrictions appropriately.
- Handle Android 13+ notification permission.
- Handle audio playback while the screen is locked.
- Do not keep a permanent background service running unnecessarily.

4. IMPORTANT SCHEDULING DESIGN

Do NOT make the Android app call the backend at prayer time.

Instead:

ADMIN
  ↓
Backend
  ↓
FCM/API sync
  ↓
Android app
  ↓
Store schedule locally
  ↓
Android AlarmManager
  ↓
Prayer time
  ↓
Play local Azan

The Android app must schedule the next prayer alarms locally.

When the admin changes the schedule:
- Backend creates a new schedule version.
- Android devices receive an FCM data message.
- App fetches the new configuration.
- App updates Room database.
- App cancels outdated alarms.
- App schedules the new alarms.

If FCM is delayed or unavailable, the app should continue using its last valid local schedule.

5. AUDIO REQUIREMENTS

The Azan should be pre-recorded.

Support:
- MP3 initially
- Download/cache the audio locally
- Verify the download
- Store the audio locally
- Play from local storage at prayer time
- Do not require internet at prayer time
- Allow admin to replace the audio
- Download new audio in the background
- Do not delete the currently working audio until the new audio is successfully downloaded and validated.

Implement reliable audio playback with Android Media3/ExoPlayer or the most appropriate modern Android solution.
